# Еженедельный отчёт — неделя с 17.08.2026 по 21.08.2026

## Общий статус

Основная работа недели — трек **Интеграция Р-Платформа ↔ NetBox** в проекте R-Platform. Проведён анализ базы данных Р-Платформы, разработана и согласована с техподдержкой целевая модель соответствия иерархии локаций. Трек поставлен на паузу до согласования целевой схемы справочника типов локаций.

## R-Platform

### Трек: Интеграция Р-Платформа ↔ NetBox

**Анализ базы данных.** Получен и разобран резервный бэкап БД `core` от 14.08.2026. Восстановлена схема: 742 таблицы, 537 функций, 6 915 индексов. Установлено:

- СУБД — PostgreSQL **11.22**, сборка `Debian 1:11.22-astra.se5.1+ci3` (Astra Linux Special Edition 1.7). Версия снята с поддержки сообществом в ноябре 2023 года, обновления безопасности не выпускаются
- Расширение PostGIS отсутствует. Геоданные хранятся в полях `jsoncoords` типа `jsonb`, вся пространственная логика вынесена на уровень приложения
- Мандатное разграничение доступа (PARSEC) включено на уровне БД, но метки всех объектов нулевые, построчный контроль отключён на всех таблицах — фактического разделения по уровням доступа нет
- Прикладной интерфейс реализован 537 хранимыми функциями `s_*` и `si_*`; функции записи (`s_set_locations`, `s_set_tags`, `s_set_equipments`) в поставке присутствуют

**Разбор формата координат.** Установлено, что `jsoncoords` содержит координаты WGS84 с перестановкой осей по конвенции 3D-движка: `x` — долгота, `z` — широта, `y` всегда ноль. Формат нигде не документирован. Дерево локаций выгружено и преобразовано в GeoJSON — 2 983 точки.

**Аудит данных.** Выгружено 3 418 записей локаций, из них 3 071 активная: 2 679 помещений, 202 этажа, 153 здания, 22 объекта, 7 функциональных групп. Выявлено 78 записей, требующих правки: 18 дублей наименований, 21 наименование с артефактами экранирования, 32 помещения, подчинённых зданию в обход этажа, 2 объекта вне структуры, 5 зданий без координат. Перечень с полными путями передан для исправления.

**Анализ справочника типов локаций.** Установлено, что подрядчиком переиспользован типовой географический справочник с присвоением ему другой семантики: `locCountry` означает «Уровень 0», `locCity` — «Наименование объекта», `locStreet` — «Блок здания». Проверкой по коду установлено, что из десяти типов в SQL-функциях жёстко адресуется только `locBuilding` (пять мест), поэтому переименование остальных безопасно. Замечания оформлены и направлены подрядчику.

**Целевая модель соответствия.** Разработана и зафиксирована:

| Уровень Р-Платформы | Модель NetBox |
|---|---|
| Административные единицы (страна, республика, округ, город, село) | `dcim.Region` |
| Объект / площадка | `dcim.Site` |
| Здание, блок, фасад, этаж, помещение | `dcim.Location` |
| Функциональное назначение | `extras.Tag` |

Ключевые принятые решения:

- **Граница `Site` — площадка, а не здание.** Обоснование: подсети нарезаны по подсистемам (СКУД, СОТ, ОПС) и сквозные по всему комплексу. У префикса в NetBox одна область видимости, поэтому сквозной префикс невозможно привязать к 153 отдельным зданиям. Разделение подсистем выполняется ролью префикса `ipam.Role`
- **Функциональное назначение выведено из иерархии в теги.** Признак сквозной и деревом не выражается: объект рекреации может содержать подобъекты критической инфраструктуры. В платформе для этого есть штатный механизм — таблица `tags` и поле `tagids` на 12 таблицах
- **`dcim.SiteGroup` не используется** — при текущем количестве площадок группировка избыточна

**Доработка Р-Платформы не требуется.** Принято решение сохранить платформу в стоковой версии для возможности штатного обновления. Установлено, что задача внешнего ключа для двусторонней синхронизации решается штатным механизмом объектных свойств: свойство с признаком уникальности `uniquefl`, поиск через функцию `s_find_by_jsonprops`. Это конфигурация, а не разработка.

**План перехода источника истины** зафиксирован в двух этапах: на первом источником остаётся Р-Платформа с ручной загрузкой в NetBox, на втором — после получения API — роль переходит к NetBox с синхронизацией в платформу средствами Ansible.

**Подготовлены материалы:** карта схемы БД, модель соответствия уровней и полей, матрица допустимых родителей, схема IPAM по подсистемам, перечень замечаний подрядчику, файлы импорта регионов и площадок в NetBox.

**Статус: пауза.** Целевая схема справочника типов локаций направлена на согласование в техподдержку производителя. Открытые вопросы: назначение типа `locStreet`, необходимость отдельного типа для стоек, синхронизация оборудования, штатность HTTP API.
